# PRIOR_ART — что уже построено вокруг этой идеи

Пять направлений ресёрча (параллельные субагенты, декабрь 2025):
parallel-in-time lineage · спекуляция в железе/компиляторах ·
GPU-исполнители программ · параллельные энтропийные кодеки ·
автоматический поиск параллельных форм. Цель каждого: «что уже есть /
где дырка / что украсть».

## TL;DR

- **Наша схема — не одно изобретение, а пересечение пяти зрелых областей.**
  Jacobi-по-траектории, Newton+scan, guess-verify по чекпоинтам — всё это
  существует десятилетиями в разных костюмах. Хорошая новость: мы встали
  ровно на стык, где каждая область знает свою половину.
- **Критическая находка:** learned-предсказатель чекпоинтов для
  произвольных программ **уже существовал** — линия ASC/Simulated
  Tunneling/NewAge (Waterland, Seltzer, Kraft; Harvard/BU/Princeton,
  2012–2018). Нейросеть + деревья решений предсказывали состояние x86
  (память+регистры), спекулятивные сегменты верифицировались — до ~44
  ядер почти линейно на «предсказуемых» программах.
- **Наш эмпирический закон доказан теоремой:** Gonzalez et al., NeurIPS
  2025 — показатель Ляпунова → константа Пойака–Лоясиевича → число
  итераций. «Ускорение = предсказуемость» — теперь цитата, не метафора.
- **Дырка, которая остаётся:** никто не делал систему «произвольный
  байткод/WASM → вся траектория как fixpoint на GPU + learned-чекпоинты +
  merge-aware верификация + гарантированный serial-фолбэк». Каждая
  компонента занята — конъюнкция свободна.
- **Трезвость от ASC:** предсказуемость реальных программ **бимодальна**
  («полностью предсказуемы или полностью нет»). Наш непрерывный спектр
  (p, a) живёт в toy-пространстве; на реальных бинарях жди два полюса.

## 1. Parallel-in-time / решение траекторий целиком

Самая глубокая родословная — 60 лет, от Nievergelt до DEER.

| Работа | Что делает | Отношение к нам |
|---|---|---|
| Nievergelt, CACM 1964 | Угадывает несколько состояний на стыках, все интервалы параллельно, итерация до совпадения | Прадед guess-verify |
| Chazan & Miranker 1969 | «Chaotic relaxation» — асинхронные fixpoint-итерации | Теория нашего Jacobi |
| Kogge–Stone 1973 | Scan для «общего класса рекуррентностей» | Наш `_scan_linear` дословно |
| Waveform relaxation 1982 | Итерации по целым сигналам (непр. время) | Наш свип = дискретный частный случай |
| Bellen–Zennaro 1989, Kiehl 1994 | Multiple shooting: неизвестные = состояния на стыках, Newton | Наш `newton` = shooting с сегментами длины 1 |
| **Parareal** (Lions–Maday–Turinici 2001); Gander–Vandewalle 2007 | Грубый пропагатор G предсказывает чекпоинты, точный F проверяет все интервалы разом | **Наш Jacobi-прогрев = coarse propagator; наша ниша «learned G» — у неё 40 лет теории** |
| MGRIT/XBraid 2014, PFASST 2012 | Многоуровневый parareal, FAS | Чего не хватает нашему Jacobi: **иерархия** |
| All-at-once Krylov (McDonald+ 2018); ParaDiag | Вся система время-пространство как одна линейная, циркулянтный предобуславливатель | Альтернатива Newton+scan для линейных f |
| **Song et al., ICML 2021** | Любой feedforward-граф как нелинейная система; Jacobi/GS свипы; точность за ≤T итераций | **Наш `jacobi` один-в-один**, но на NN-графах |
| **DEER** (Lim+, ICLR 2024) | Newton по длине последовательности, бидиагональный якобиан через associative scan | Наш `newton` — признано в README |
| **ELK / quasi-DEER** (Gonzalez+, NeurIPS 2024) | Диагональный quasi-Newton O(T·d)/свип; LM-демпфирование через параллельный сглаживатель Калмана | Строго лучший Newton — брать |
| **Gonzalez+ NeurIPS 2025** | λ_max → PL-константа → число итераций; хаос → экспоненциальная деградация обусловленности | **Теорема под нашей таблицей** |
| Gonzalez+ Sep 2025 | Единый фреймворк: все методы = «линеаризуй f → LDS → scan» | Наша таксономия: jacobi = тривиальная линеаризация, newton = полная |
| ParaDiGMS 2023 | Picard-итерации по траектории диффузии, окна | Тот же свип; окна — крадём |
| Jacobi/Lookahead decoding, CLLM 2023–24 | Guess-траектория токенов → verify → iterate; CLLM **дообучает f сжиматься** | `spec_decode.py` = это; важно: «делать f сжимающей» = наш вывод про AV1 |

**Что уже дублируем не зная:** Jacobi = Song 2021 = ParaDiGMS; Newton =
DEER = multiple shooting; прогрев 0→8→32 = coarse propagator; FSM-heal
на reset'ах = state merging (Mytkowicz); «позиция t точна после t свипов»
= классический результат Jacobi на треугольной системе (Bellen–Zennaro
1989).

## 2. Спекуляция в железе и компиляторах

| Эпоха | Работа | Суть |
|---|---|---|
| 1964–2001 | Nievergelt → Multiscalar 1995 → Hydra → STAMPede 2000 | TLS: спекулятивные потоки, squash-rollback |
| 1996–2001 | Lipasti value prediction; Jiménez–Lin perceptron | Learned-угадыватели, которые **дошли до железа** (Samsung M1–M6, AMD Zen) |
| 2000–02 | Slipstream; **MSSP (Zilles & Sohi)**; Cintra–Torrellas | «Дистиллированная программа» предсказывает live-ins; обучение когда/чему доверять |
| 2001 | Speculative precomputation (Collins); Spec. срезы | Live-ins вычисляются срезами, не учатся |
| 2005–10 | Mitosis; BulkSC; CorD; state separation + multi-value | Live-in предсказание, энумерация кандидатов |
| **2012–18** | **ASC / Simulated Tunneling / Computational Caches / NewAge** | **Learned-предсказание полного состояния x86, спекулятивные сегменты, до ~256× в симуляции** |
| 2013 | Intel TSX | HTM shipped → errata → вырезан ~2021; потолок = L1 |
| 2014–25 | Mytkowicz FSM; principled/enumerative speculation; path fusion; GSpecPal | FSM-спекуляция: энумерация всех состояний, merge, до 95× на Xeon Phi |
| 2023–24 | Speculative/Jacobi/Lookahead decoding | Наш алгоритм, задеплоенный, в LLM-инференсе |

**ASC — почти точно наша ниша, занятая в 2014.** Отличия, которые остаются:
(a) ASC верифицирует **последовательно** от главного потока и ускоряется
на хитах — у нас вся траектория перепроверяется параллельно каждый свип
(расписание Parareal, не TLS); (b) у ASC нет merge/heal — предсказание
либо точное, либо промах; у нас траектория «заживает» между чекпоинтами;
(c) они меряли бинарный расклад «предсказуемо/нет» — мы меряем континуум
и называем его законом; (d) их предсказатели — деревья и мелкая NN 2014
года; современный learned-predictor (трансформерного масштаба) для
чекпоинтов никто не ставил.

**Теория «заживления» — синхронизирующие автоматы:** гипотеза Черни
(слово сброса ≤ (n−1)²; для апериодических доказано n(n−1)/2, Trahtman;
случайные DFA синхронизируются w.h.p. с длиной ~O(√n·log n)).
Парный автомат A⁽²⁾ (O(n²|Σ|)) позволяет **предвычислить** ожидаемое
расстояние заживления без прогона — предиктор нашего числа свипов.

**Потолки TLS (почему не взлетело):** спекулятивное состояние ≤ кэша;
squash-всех-преемников O(T) на нарушение; каскад промахов; затем Spectre
отравил идею. Loopapalooza (ISPASS'21): потолок 4.6–7.2× на реальном
железе.

## 3. GPU-исполнители программ

| Система | Что исполняет | Как | Урок |
|---|---|---|---|
| VectorVisor (ATC'23) | **Немодифицированный однопоточный WASM**, N независимых инстансов | **Бинарная трансляция** wasm→OpenCL, continuations, interleaved layout | Якорь «wasm на GPU»; throughput, не latency |
| wasmgpu | WASM-инстансы + WASI на wgpu | Два режима: opcode-интерпретатор и compiled-диспетчер по basic-block адресам | Compiled > interpreted |
| GVM (OOPSLA'19) | Полная JVM на GPU: объекты, исключения, dyn-dispatch | Интерпретатор на поток + profile-guided warp-assignment | Можно, но divergence съедает |
| Rootbeer/Aparapi/TornadoVM | Ядра Java, не авто-параллелизм | Трансляция байткода | «Пишешь параллельное — гоняем на GPU» |
| CuLE | Эмулятор Atari 2600 целиком | CPU-интерпретатор на поток | VM-per-thread работает |
| FMAG | **Одна инструкция на все позиции** — PC униформен | Conditional writes вместо ветвлений | **Убить divergence радикально** |
| Madrona | ECS-симуляции, N инстансов | Группировка по instruction-stream coherence | Сортировка по PC |
| Hazy/Megakernels | LLM forward как софт-VM на SM | Warp-специализация ролей | Для толстых состояний |
| Query-engines (MapD→OmniSci, Saber, Excalibur) | Реляционные операторы | **Все бросили интерпретацию** ради JIT/fused megakernels | «Декодинг байткода на GPU — дорого» |
| GPU-TLS, Paragon, Time-Warp-on-GPU | Спекуляция на GPU | Dependence-check + re-execute; checkpoint+rollback | Спекуляция на GPU делалась, не fixpoint |

**Вердикт:** «wasm→GPU» занято тонко (VectorVisor — единственная
рецензируемая веха, остальное хобби-уровень). «Одна последовательная
программа быстрее на GPU через fixpoint/спекуляцию» — **открыто**.
Ближайшие: GVM (любая программа, без спекуляции) и GSpecPal (спекуляция,
только FSM).

**Флаг риска от субагента:** у VM-функции `f` **нет якобиана** — Newton
умирает на байткоде, Jacobi выживает. Для дискретного случая честный
позиционинг — «обобщение FSM-спекуляции + MSSP на произвольный байткод».

## 4. Параллельные энтропийные кодеки

Наш замер «адаптивный арифметический декодер не угадывается» — подтверждён
теорией дословно:

- **Moo & Wu, DCC'99:** ресинхронизация AC после неизвестного отрезка b
  бит — O(2^{b/2}); «prohibitively high» при b≳100. Механизм нашей
  десинхронизации описан: неверный CDF → другие ренормализации → потеря
  битовой позиции навсегда.
- VLC-коды наоборот **самосинхронизируются** (Ferguson–Rabinowitz 1984,
  T-codes, Maxted–Robinson): наш FSM-reset эксперимент — то же явление.
- CABAC-спекуляция существует в железе и упирается в ~2 бина/такт
  (branch-selection 2-bin engines, патент TI). Ответ индустрии — тот же
  наш: **переделать формат** (HEVC: bypass-группы, WPP <1% потерь).
- AV1 **уже отгружает** наш вывод: `disable_cdf_update` бит,
  `frame_parallel_decoding_mode`, per-tile реинициализация CDF.

Цена параллельности у реальных форматов (совпадает с нашей кривой):
~1–6% покупает 3–15×; ~10–22% — 30–125×. Дешёвый режим кончается, где
фиксированные затраты чанка перестают амортизироваться.

| Формат | Единица | Цена | Параллелизм |
|---|---|---|---|
| Наш demo (CDF reset) | чанк C символов | +1.2%→+22% (3→125 чанков) | = #чанков |
| **Recoil (PPoPP'23)** | сплит в точке ренорма, **состояние хранится (~16 бит)** | <0.15% типично | до 16+ сплитов, адаптивно |
| nvCOMP ANS | независимые чанки ×8 под-потоков | заголовки чанков | тысячи чанков |
| JPEG XL | group 256² px + TOC | group-заголовки | ~135 групп на 4K |
| FFV1 | slice, RC-контекст на slice | «увеличивает размер» | **4K: 400 fps GPU vs ~100 CPU (реальный замер FFmpeg/Vulkan)** |
| zstd literals | 4 interleaved FSE | ~+7.3 B/секцию | 4-way ILP |
| zstd frames | независимый фрейм | 6.6% @16KiB, 10% @4KiB | per-frame |
| Interleaved rANS (Giesen) | N состояний в одном потоке | ~0 метаданных | SIMD/GPU |
| HEVC WPP | CTU-строка + warm-start контекста | <1% | = #строк |

**Дизайн-уроки:** (1) Recoil — храни состояние, оно ~16 бит, не угадывай;
(2) warm-start вместо reset (WPP): CDF из снапшота вместо дефолта —
режет нашу 1–6%; (3) learned-CDF + точный кодер (L3C/torchac/Bit-Swap):
параллелизм живёт в **латенте**, не в контексте — автогрессивный контекст
возвращает цепочку; (4) статический/переданный CDF → единственное
состояние = `(lo,hi,val)` — верификация тривиальна; (5) энумеративная
спекуляция ANS: состояние ≤2¹⁶ — GPU перебирает всё, нужен CRC-оракул
на чанк.

## 5. Автоматический поиск параллельных форм

**Универсального компилятора «последовательное→GPU» нет** — три слоя
причин: анализ зависимостей неразрешим (Rice) и неточен на указателях;
параллелизм надо **изобретать** (синтез, не анализ); P≠NC запрещает
гарантию вообще.

| Система | Класс программ | Как находит параллелизм |
|---|---|---|
| Futhark | Чистый функциональный, SOACs | **Не ищет** — программист даёт ассоциативные оп; incremental flattening |
| Accelerate, Dex, SaC, Taichi, Bend | Ограниченные языки | Параллелизм манифестен в языке/эффектах |
| ppcg / Polly / Pluto | Аффинные статические гнёзда (SCoP) | Полиэдральное планирование; ppcg — ближайший «clang→GPU» |
| DaCe/SDFG | np/PyTorch→граф | Map-узлы + LoopToMap; white-box трансформации |
| **Parsynt** | Циклы над read-only коллекциями | **SyGuS-синтез join-функции** + Dafny-доказательство |
| **SYMPLE** | Стилизованные C++ UDA | Символьное исполнение + частичная подстановка на конкретном входе |
| Fisher & Ghuloum 1994 | Циклы→scans/reductions | Тело цикла = функция; поиск замкнутой формы композиций |
| Morita+ (3rd homomorphism) | foldl+foldr пары | D&C-форма **гарантированно существует** — оракул «тратить ли бюджет» |
| Sato & Iwasaki 2011 | Редукции/scans | Композиция тела = **матричное умножение** (max-semiring) |
| Mytkowicz FSM 2014 | Конечные автоматы | Энумерация стартовых состояний, merge — guess-verify дословно |
| Perspective/Privateer | Общий C/C++ | Runtime-спекуляция поверх неточного анализа; ~23× на 28 ядрах — потолок классики |
| KernelBench/Kevin-32B/CUDA-L1 | PyTorch→CUDA | LLM-предлагает, execution-feedback; **без гарантии корректности** |
| nvc++ -stdpar | C++17 parallel algorithms | Semantics execution policies; продакшн |

**Урок фронтира:** LLM-ас-proposer безопасен ровно там, где есть
верификатор, — то есть **внутри нашего guess-verify цикла**.

## 6. Вердикт по новизне — честно

| Компонент | Статус | Ближайший приорат |
|---|---|---|
| Jacobi по всей траектории | Занято | Song ICML'21, ParaDiGMS, waveform relaxation |
| Newton+scan | Занято | DEER (у нас честно назван), multiple shooting 1989 |
| «Ускорение = предсказуемость» | Занято (теорема) | Gonzalez+ NeurIPS'25; наша таблица = экспонат |
| Guess-checkpoints + parallel verify | Занято | Parareal 2001, MSSP 2002, spec decoding 2023 |
| **Learned-предсказание чекпоинтов** | **Занято** | **ASC/NewAge 2012–18 — главная находка ресёрча** |
| WASM→GPU исполнение | Тонко занято | VectorVisor (throughput, не speculation) |
| FSM merge/heal | Занято | Mytkowicz, enumerative speculation, синхр. автоматы |
| AC-стена при адаптивной модели | Занято (теория) | Moo & Wu 1999; наш замер = подтверждение |

**Что остаётся нашим** (конъюнкция, каждый член по отдельности занят):
1. Один исполнитель для произвольного байткода, где вся траектория —
   fixpoint на GPU (не per-chunk TLS-верификация, а Parareal-расписание).
2. Learned-чекпоинты **современного** масштаба + merge-aware верификация
   (ASC не знал heal; FSM-литература не знала learn).
3. Измеренный континуум «предсказуемость→глубина» как характеристика
   (f, вход), с pair-automaton предвычислением.
4. Гарантированный serial-фолбэк и точность по построению — как единый
   инвариант, а не отдельная фича.

Честный позиционинг: «обобщить FSM-спекуляцию + MSSP + parareal на
произвольный байткод, с learned G и merge-осведомлённой верификацией».
Это защитимо — если рецензент сольёт «solver framing» и «speculation
framing», новизна сужается до единой рамки + измеренного закона.

## 7. Что украсть — ранжировано

**Дёшево (~15–30 строк), высокая цена:**
- **Anderson acceleration** на Jacobi-свипы (m≈5–10): на линейных f ≈
  GMRES — a=0.9 должно упасть с ~300 свипов до десятков без якобианов.
- **Freeze converged prefix:** маска `done`, не пересчитывать устоявшиеся
  позиции — ~2× работы даром.
- **quasi-DEER:** диагональная/secant-аппроксимация якобиана вместо d
  batched f-вызовов — O(T·d) вместо O(T·d²) на свип.
- **LM-демпфирование внутри скана (ELK):** λ к каждому якобиану шага —
  «расходится на хаосе» станет «ограничено, но медленно».
- **Commit-префикс немедленно** (как spec decoding): wall-clock =
  позиция первого расхождения.

**Средний труд, высокая цена:**
- **Двухуровневая схема parareal:** G = Jacobi на каждом k-м шаге →
  потом learned G. Формальная машина для «checkpoint guesser» уже
  написана за нас.
- **Неравномерные shooting-сегменты:** неизвестные только на стыках/
  точках высокой кривизны — память T·d → (T/k)·d.
- **Jacoby-free Newton–Krylov:** для больших d — matvec через f + GMRES
  без T×d×d якобианов.
- **Blelloch work-efficient scan:** O(T) работы при той же глубине.
- **Pair-automaton предвычисление merge-дистанции** для FSM-кейсов —
  предиктор свипов без прогона.
- **Compiled, не interpreted f:** урок MapD/VectorVisor — wasm→GPU-ядро
  с диспетчером по basic-block адресам, интерпретатор только для bring-up.
- **Сортировка позиций по PC** перед диспетчем (GVM shape-matching).

**Фронтир:**
- **Top-k энумеративные чекпоинты** (k=1 ASC ↔ k=n Mytkowicz; TOPC 2020):
  k по confidence предсказателя.
- **Чекпоинты в точках merge:** ставить там, где парный автомат говорит
  о слиянии — неверные догадки дёшевы, потому что заживают быстро.
- **Предсказывать классы эквивалентности состояний**, не состояния
  (Computational Caches) — цель сжимается драматически.
- **CLLM-рычаг:** «делать f более сжимающей» — resets, segment boundaries,
  segmented scans; если контролируешь формат — это главный рычаг вообще.
- **Confidence-gated верификация** (ISCA'98 estimators): коммитить
  низко-уверенные позиции последними / энумерировать их.

**Чего не исправить:** хаос и крипто — теорема (экспоненциальная
обусловленность) + P-полнота. Формулировка остаётся «worst case = serial».

## 8. Обновлённая картина архитектуры

```
clang/rustc → wasm ──┬─→ compiled GPU-ядро f (basic-block dispatch,
                     │    не opcode-интерпретатор)
                     ├─→ Jacobi/AA-свипы по траектории (fixpoint-сертификат)
                     ├─→ Newton только где f дифференцируема (числовые
                     │    подпрограммы), иначе — Jacobi/энумерация
                     ├─→ learned G (parareal coarse propagator):
                     │    top-k состояний + confidence, чекпоинты
                     │    в merge-точках, классы эквивалентности
                     └─→ commit-префикс + serial-фолбэк (invariant)
```

И отдельная линия — **format-level**: если контролируем продюсера,
reset/warm-start чанки + TOC (Recoil-паттерн: хранить 16-битное состояние
вместо угадывания) превращают непараллелизуемое в тривиальное за 1–6%.
