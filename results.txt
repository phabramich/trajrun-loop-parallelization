=== wasm -> batched-VM -> Jacobi-trajectory (2026) =====================
Pipeline: rustc --target wasm32-unknown-unknown -> wasm_load.py (restricted
decoder, ~30 opcodes) -> vm_ref.py (scalar interpreter) -> vm_metal.py
(batched lanes: pc+locals+stack, MLX/Metal или np_shim) -> vm_exec.py
(chunked Jacobi over instruction boundaries, probe2 guesser).

Programs (wasm-progs/src/lib.rs):
  fsm_lex       -- quote/escape FSM, hard reset on \n (merge point)
  sat_acc       -- acc = clamp(acc+x, +-1e6) (clamp attractor)
  adpcm_decode  -- IMA ADPCM: carried (predictor, step-index)  [WALL]
  hash_chain    -- FNV-like multiplicative chain               [WALL]

Results (NumPy backend, B=chunks, K = multiple of loop period):
  csv 32KB fsm_lex : 1,900,557 steps, 513 chunks,   3 sweeps
                     crit-path 11,136 = T/170, exact 514/514, out bit-exact
                     t_ref 0.84s / t_par 7.1s
  sat 8K i16, bias 12k: 233,508 steps, 82 chunks,   2 sweeps
                     crit-path 5,700 = T/41, exact 83/83, out bit-exact
                     t_ref 0.10s / t_par 2.5s
                     (verify: 81/81 lanes with acc:=garbage merge bit-exact)
  adpcm 1K samples : 112,660 steps, 65 chunks, wavefront +1/sweep -> WALL
                     (acc error is a persistent offset; clamping never fires)
  hash 8KB         : 200,733 steps, 129 chunks, wavefront +1/sweep -> WALL

Performance honesty:
  * Dispatch-bound interpreter: 1 step ~0.57ms (numpy, B=512) / ~8.4ms
    (MLX, launch overhead). mx.compile made it WORSE (134ms/step).
  * t_par > t_ref everywhere: the win is in critical-path STEPS
    (sweeps x K << T), not wall-clock, at this batch scale.
  * Metal pays off only at B >> 10^3 or with a compiled/lowered step fn.
  * Loop-period alignment matters: variable-length iterations need K
    multiple of the instruction pattern period (sat: 57 instr/4 bytes),
    else boundary pc drifts and nothing merges.

=== wasm_metal.py: WASM -> Native Metal Kernel (mx.fast.metal_kernel) ==
Fixes both walls:
  1. Engineering wall: transpiles flat WASM into native Metal Shading
     Language with register locals/stack (uint l*, s*) and fused basic-block
     do-while loops. 1 sweep of 15M-31M WASM steps takes ~1-2 ms on Metal.
  2. Algorithmic wall:
     - Prologue alignment (loop_pc, depth=0) + probe3 (d2 == 0 separates
       linear induction counters from dynamic carried state).
     - Contractive state design: adpcm_leaky (15/16 leak on both pred and
       index, G.726/G.722 style) -> 100% trajectories heal in ~180 samples.
     - Finite-state Enum+Scan on Metal (3xC lanes + log2(C) scan): solves
       fsm_lex in 1 rollout + 10 scan steps even on pure Z_2 quote streams
       (no \n, no \) where Jacobi hits a group-theoretic wall.

=== Update: event-based chunking, auto-EnumScan, opcode coverage ===

1. Back-edge iteration counting (root fix for variable-length bodies).
   Chunk = K loop iterations (counted inside emitted br/br_if -> loop_pc),
   not K instructions. Boundaries are always at the loop header (depth=0),
   so pc never drifts: Jacobi heals on br_table/variable-length bodies,
   and enum tuples shrink (pc constant). Verified on nibble_fsm
   (br_table + i32.rem_u, per-arm path lengths differ): [126, 0], bit-exact.

2. run_auto: probe3 -> Jacobi -> on stagnation auto-enumerate OBSERVED
   state tuples (pc + dynamic locals, additive deltas for linear locals
   via semidirect product), feed real exits back, let Jacobi certify.
   - Z_2 quote FSM (no hints): [958, 551, 551, 0], bit-exact, |S|=41.
   - Honest wall when domains don't close (ADPCM/hash).
   - Predictor (1 extra rollout on first bad sweep): perturb only
     carried cols (exit-entry delta non-constant) -> merge_frac; 0 means
     "no healing in-chunk" -> enum immediately; >0 means Jacobi viable.
     False-negative sources fixed: compare exits against E_np (aligned),
     never perturb counters/params (constant exit-entry delta).

3. Opcode coverage: br_table (parser cursor bug fixed + MSL switch),
   f32 arithmetic/comparisons/conversions incl. 0xFC trunc_sat
   (rustc `as u8`), spec-correct opcode table (i64 cmp 0x50, f32 cmp
   0x5B, f32/f64 arith blocks). float_leak (f32 IIR lambda=7/8):
   [126,125,4,0] bit-exact vs scalar AND sequential Metal.
   Deferred honestly: call/call_indirect (needs frames or inlining),
   f64 arithmetic (decoded, no u64 stack slots), i64 arith same.

4. Threadgroup input cache: SKIPPED after measurement. Kernel is
   dispatch-bound: ~260 MB/s input reads vs ~200 GB/s available (0.1%);
   lanes stream disjoint input regions -> zero reuse by construction.
   A shared-memory stage cannot help either property.

5. Negative result kept for the record: Anderson acceleration hurt the
   discrete FSM case (5->9 sweeps) -- linear mixing injects invalid
   automaton states; left off by default (reverted in 6013741).
